# 可变深度搜索与 AlphaGo 类比

更新日期：2026-09-17 UTC

## 当前“慢一拍”是什么

mixture 检查的是中点 q 与中心差分速度 `l=(x_right-x_left)/(2dt)` 的关系。生成一个右邻点后，才能检查前一个中点，因此这是几何定义带来的延后一拍，不是 GRU 的训练延迟。

## AlphaGo 对应关系

AlphaGo/AlphaZero 的关键不是把网络无限加深，而是“策略先验 + 可变深度树搜索 + 价值评估”。在本项目中可对应为：

- policy prior：GRU 的 `p(event|state)` 与 `p(q'|event,state)`。
- action：先抽 event，再抽 q′，执行该 `(q,q′)` 的 F。
- state：历史、q、GRU hidden、事件/路径记忆。
- value：预测未来多步的误差、q/历史矛盾、mixture 拒绝风险和完成概率。
- tree search：在没有真实未来的模型内部展开候选分支。
- commit：只提交根节点选出的第一步，然后滚动重搜（receding horizon）。

## 推荐机制

每个搜索节点严格执行：读概率 → 抽 event → 在 event 内抽 q′ → 执行 F → 更新历史/hidden → 检查中点。扩展若干分支后，按策略先验和价值函数做 PUCT/beam/particle search。深度不是固定 H：至少展开 `D_min`，若候选价值差距小、q熵高或检查边界不确定，就继续到 `D_max`；若根动作后验已稳定、相容性余量大且价值方差低，就提前停止。只提交根动作，搜索中的未来点不直接输出。

## 训练

先用离线真值生成训练前缀和自由 rollout，训练 value head 估计有限视野回报，例如：

`V(s)=E[-Σ_k γ^k (endpoint_error_k + λ contradiction_k + μ reject_k)]`

推理时 value head 不接收未来真值。策略头可沿用当前 GRU；搜索只改变动作选择，不反向改写 q，也不通过检查器 argmax 反推 event。应使用按视频划分的开发选择和多步自由 rollout 目标，不能只用一步 q-NLL。

## 两种“可变深度”必须区分

1. 可变深度搜索：AlphaGo 类，优先实现；网络大小不变，计算预算随节点难度变化。
2. 可变深度网络计算：让 GRU 反复 ponder，类似 ACT/halting；会增加训练复杂度，不能替代树搜索，因为它不显式比较不同 event/q′分支。

## 主要风险

- 分支因子最多约 `events × q = 64`；必须用 top-k policy、beam 或 PUCT，不能穷举所有 F 后挑最像真值的路径。
- mixture 的硬 reject 会改变搜索分布；需要把拒绝概率/分数纳入 value，或改成软似然和粒子权重。
- value 学错会把搜索引向稳定但错误的轨迹；必须报告 root action 与无搜索基线的多步对照。
- 搜索增加的是推理计算，不会自动产生新的 event 容量或连续分布。
- 最后仍需保留完成率、回退次数、q/历史矛盾、energy score 和校准覆盖率，不能只看搜索后的点误差。

## 原型实测与速度优化（2026-09-17）

最新进展：接口错误已修复并补测，修正后消融及价值模型训练见 `corrected_search_experiments.md`。下方原始实验数字保留作为历史记录，不能当成修正后效果。

后续诊断纠正：原型 `_child` 与批量 `_expand` 都把含中点的 `history[:, -2:]` 传给 checker 的 left_history；checker 实际取该历史最后一点，导致用 `(right-middle)/(2dt)` 而非 `(right-left)/(2dt)`。恒速合成输入现场验证为 50 对正确 100。此前原型结果不能用来判断可变深度或正确 mixture 约束的效果；速度优化只保持了这一错误实现的行为。尚未在本次诊断中修改搜索代码。此前记录的测试失败率 0.01656 是跨时间平均，50 步端点失败率实际为 0.03125（2/64 窗口）。

隔离原型已在开发集和测试集运行。开发集使用 32 窗口、2 粒子、50 步；固定深度 1/2 的 50 步 embedding RMSE 分别为 0.04109/0.03514；最小深度 2、最大深度 3 的提前停止版本平均深度 2.29、RMSE 0.03535，失败率 0。测试集使用 64 窗口、2 粒子、50 步，同一可变深度配置的 RMSE 为 0.11557/0.07882/0.18040（10/25/50 步），失败率 0.01656；这说明当前贪心 beam 原型尚未成为可靠的预测升级，不能替代官方随机粒子基线。

原始实现的测试集运行约 225.9 秒；优化后约 31.4 秒，约 7.2 倍加速。优化只改变计算组织：同一搜索节点的多个 q′ 候选批量执行冻结 F、mixture 和 q 诊断；温度为 0 时相同初始状态的重复粒子只计算一次再复制结果。开发集指标逐项保持一致，v20-rnn-mixture 的 16 项机制测试仍全部通过。非零温度仍保留独立粒子路径，不使用复制捷径。

把 `OPENBLAS/OMP/MKL` 限制到单线程后，开发集耗时仍约 15.5 秒，与默认环境的 15.6 秒几乎相同；目前主要收益来自批处理和去重，而不是强行指定 120 个线程。
