# 真实模型混合梯度小预算训练与固定复核

2026-09-17。脚本 `train_hybrid_writer.py`、`validate_hybrid_writer.py`；结果 `adaptive_search_results/hybrid_writer_pilot.json` 与 `hybrid_writer_validation.json`。

## 预定方法

原F/GRU冻结，每步只增加二维常数角偏置 `theta*bound`，bound来自既有10TRAIN拟合视频cap的1%：[4.420470599e-5,7.863518817e-5]rad。theta初始0、每步投影[-1,1]。

优化seed1901/2718/3141，各4次Adam更新，lr=.1，梯度norm裁1。每次重新抽10拟合视频前半段各1个300步窗口、P4，窗口seed=seed*100+iteration，窗口j动作seed=seed*10000+iteration*100+j。逐窗口反向后平均梯度节省内存，但没有截断时间梯度。

目标为50/100/300步U-energy平均，路径损失正常求导；score项用detach(集合损失−留一粒子基线)乘该粒子完整300步logprob再求和，不误除以P。完整路径score对较早目标也包含未来动作：在满足常规可微条件时这些未来项期望为0，但可能增加方差，下一步应单独验证。

任一粒子失败或任一非有限梯度会跳过整次更新，不nan_to_num掩盖问题。硬失败边界的全局无偏性仍未证明。本次12次更新没有失败/非有限/跳过，所有梯度norm都超过1（原始39.54–4949.49）。这不是固定状态上的方差估计，因窗口和参数都在变。

训练反向总时间161.37秒，单次约13.4秒；过程中观测进程RSS约800MB，不称严格峰值。CPU单线程，无必要启用120线程。

## 日志修正

初次运行发现 `theta.grad=total` 后原位梯度裁剪会改变待记录的原始total。明确终止该进程，改为 `theta.grad=total.clone()`，重新运行完整协议。没有改变训练更新规则，重跑第1次参数和评分与原日志完全一致。报告保留未经裁剪的混合梯度，避免与路径梯度比较时混淆。

## 验证与下一步

116项测试通过，新增验证Torch多时距目标与NumPy U-energy一致、logprob导数正好为留一优势、detach优势不额外污染路径梯度。原F/GRU SHA与桥接审计相同。

下一步固定theta和窗口，配对比较完整路径score与每个时距只使用对应前缀logprob的因果估计器；先穷举小例验证期望一致，再比较多动作seed上的梯度稳定性。不要把增加训练次数或增大网络当作当前已证明的解决方向，也不因这次小预算失败否定所有混合梯度方法。
