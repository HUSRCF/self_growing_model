# 闭环writer固定候选的随机排序稳定性

2026-09-17。`audit_writer_ranking.py`、`summarize_writer_ranking.py`；报告 `writer_ranking_audit_seed{1901,2718,3141}.json` 和 `writer_ranking_summary.json`。

## 预定协议

取3优化种子的第1/6/12轮，共9集合，不按成功/失败挑集合。每组重建原TRAIN10拟合视频各2窗口，核验video/start与原3候选评分逐项相同；固定候选，只以新动作seed81017–81022重复P4/300步完整评估。原训练报告SHA未变，无模型更新，无留出/DEV/TEST。本轮采样不用于部署选择。

## 结果

- 原9轮中7轮接受非零更新。这7次的原当批目标差平均−.0287381；换6种子后，同一更新相对同一当前参数的平均差变成+.00432168（正值有害）。其中4/7次的复测均值有害。
- 原赢家在新单种子上的一致率38.89%；原赢家与6种子均值赢家仅3/9集合相同。
- 例：2718第1轮原改善−.0357120，复测均值+.0382780、条件RNG SE .0122607；5/6新种子选择保留原参数。
- 也有可复现收益：2718第6轮原选候选2，复测相对当前参数仍改善−.0152409，但6种子均值最优是候选1；不能把所有更新都称噪声。

将6种子分两组、各3次平均，赢家一致仅2/9；用第1/第4个单种子相比较为5/9。组1选出的候选在组2评分、反向亦然，18个交叉差均值+.00520278。样本很少且相关，不能由此断言3次平均普遍更差，也不能声称简单平均已经解决排序问题。

这里混合了正常阶段与已有更新后的状态分布，窗口/视频/随机流有重叠；只做描述性诊断，不将9集合或54赢家当独立视频样本，也不证明模型容量不是问题。训练时共享候选间RNG能配对，但不保证方差足够小。

## 决策

单批赢家更新的可靠性确实是当前问题之一，训练当批收益大幅缩水/翻转。先提高候选评分可靠性，再扩大参数或更新次数。下一步可在固定候选上比较相同粒子步预算的“更多粒子一次评估”与“多个小粒子集合平均”，报告配对差方差与赢家复现率；现有3次均值证据不足以直接改训练默认。

72测试通过，包含赢家翻转/保留当前参数/两组交叉评分检查，原分布评分/窗口因果隔离仍通过。模型、默认、冻结包不变，长期目标继续。
