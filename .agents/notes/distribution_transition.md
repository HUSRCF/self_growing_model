# 从点预测到分布预测：当前状态与建议

更新日期：2026-09-17 UTC

## 代码事实

`v20_rnn_mixture/engine/runtime.py` 每次粒子运行时从 `p(e)` 抽一个事件，再从 `p(r|e)` 抽一个下一 q。`v20_rnn_mixture/engine/dynamics.py::execute_rule` 对选中的 `(q,r)` 返回确定的下一角度候选；没有采样连续 latent、残差或观测噪声。

因此当前有三种不同含义的“分布”：

1. 事件和 q 的 categorical 分布：每个粒子最终只选一个类别。
2. mixture 的 `p(l|q)`：三分量二维速度密度，只用于相容性打分和拒绝/回退。
3. 粒子集合：由离散抽样和回退路径形成的经验云，不是明确归一化的连续后验；报告明确不把它当精确全局后验。

连续角度本身仍是点候选。当前 mixture 也不是 mixture-of-experts 或 VAE 解码分布。

## mixture 拒绝后的实际处理

它不是先生成一整个粒子集合再统一过滤。每个粒子有自己的搜索树节点：先抽 `e,r`，由确定性 `F(q,r)` 生成候选右点，再用中心差分速度和“中点寄存器 q”的 `p(l|q)` 相容性分数检查。分数超过 q 的固定阈值时，运行时恢复该粒子的父节点历史、q 和 GRU hidden，把导致失败的目标 q 加入禁用集合，然后重新抽 event/目标 q。

当前 GRU 没有 event 专属提交记忆，因此同一父节点和同一目标 q 的不同 event 会产生相同未来；代码可以按目标 q 禁用。若所有候选都被拒绝、数值失败或预算耗尽，该粒子停止，后缀标记 `failed`，存储值只是占位，不应当当作有效预测。测试表的完成率100%表示这些运行没有最终停止，不表示没有发生回退；冻结主模型仍平均发生约3749次回退。

检查的是当前中点的登记 q，而不是直接把新抽到的 `r` 用密度 argmax 改写。接受后才提交新点和 `r`；诊断 q 也不会反向覆盖寄存器。

## 推荐的渐进式分布化

第一步不必立即引入 VAE：让每个 `(q,r)` 的 `F` 输出条件残差分布或三分量 mixture，训练目标使用连续 NLL，而不是只返回均值。可写成：

`p(y_next | H,q,r,h) = Normal(y_mean=F_mean(H,q,r,h), Sigma(H,q,r,h))`

或使用条件 MDN/GMM。每次选中 `(e,r)` 后，再抽连续残差得到 `y_next`。现有 `p(l|q)` 可以作为软似然/能量项，而不是只做硬 reject；需要单独评估硬回退带来的选择偏差。

## VAE/VRNN 方案

若需要真正的 latent distribution，使用连续 latent `z`，不要把 VAE 的 `q_phi` 与离散状态 q 混淆：

`p(e,r,z,y_next | S_t) = p(e|S_t) p(r|e,S_t) p(z|S_t,r) p(y_next|H,q,r,z)`

训练时可使用条件后验 `q_phi(z|H,q,r,y_next)`，推理时只使用先验 `p_theta(z|S_t,r)`。解码器必须输出 likelihood（高斯、GMM 或其他参数化），只输出均值仍然是点预测。若要长期稳定，需要 sequence VAE/VRNN 风格的多步 rollout 目标，而非只优化一步重构。

## 预期风险

- VAE 不会自动增加 event 容量；它增加的是连续隐变量的多样性。
- 用 MSE 解码会回到平均点/模糊预测；应使用 NLL、CRPS/energy score、覆盖率及多步误差。
- 单步分布可能在递推时失稳，必须做自由 rollout 评估。
- mixture 作为硬过滤器会改变样本分布；改成软权重后要重新定义粒子权重和评分。
- q/历史矛盾、回退次数和概率校准必须一起进入模型选择，不能只看 q 相容性。
