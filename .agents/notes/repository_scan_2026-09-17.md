# 仓库扫描补充

扫描日期：2026-09-17 UTC

## 新增必要事实

- 当前工作区有四个已解压版本目录：v17、v18、v20_complete、v20_rnn_mixture；没有独立 v19 目录/ZIP，v19 证据嵌在 v20_complete 的 `reference/` 中。
- `v20_rnn_mixture` 的原始请求明确要求比较错误 q 的中心差分速度 `l` 与错误 q 的关系，和正确 q/正确轨迹对应的关系；实现采用 `p(l|q)` 三分量二维 GMM 相容性分数与 q-specific 阈值，而不是额外训练一个正确/错误分类器。
- q 是四阶因果导数指纹的聚类标签；mixture 只用中心一阶速度检查 q 相容性，因此不能保证完整四阶状态或整条未来轨迹正确。
- q 分区使用8类、9点模板、权重 `[1,1,.45,.45,.2025,.2025,.091125,.091125]`；F 保持冻结的 q-pair MLP/多项式50/50规则。
- GRU 训练只用13个训练视频前半程的28,830个转移；q、F和频率对齐先验继承了曾使用完整训练视频的数据，不能把整套模型描述为“只看过前半程”。
- `geometric` 与 `mixture` 是同一个检查器的 CLI 别名；其他旧检查器被显式拒绝。
- mixture 阈值为每个 q 在4个校准训练视频前半程上的99%经验分位；拟合使用9个训练视频前半程的19,865个中心，校准使用8,952个中心。
- 检查器对每个候选粒子分支执行回退搜索；拒绝时恢复父节点 q/历史/hidden、禁用失败目标 q、重抽 event/q′。完成率100%不代表零回退。

## 现场复验状态

在当前 Python 环境用 `PYTHONDONTWRITEBYTECODE=1 python -m unittest -v tests.test_engine` 现场运行 v20-rnn-mixture 机制测试，16 项均通过（约 2.2 秒）。归档中的 `audit/mechanism_tests.json` 也保存了交付时 `passed: true, errors: 0`。当前环境已经有可用的 SciPy；没有擅自安装依赖或修改冻结包。

## 当前最关键的研究缺口

新包把用户提出的局部 `l/q` 自洽检查接入了运行闭环，但连续角度仍由确定性 F 产生点候选；mixture 是过滤/回退器，不是未来连续分布。若继续发展，应先决定要把它变成软似然/粒子权重，还是让 F 输出条件残差分布，再考虑 conditional VAE/VRNN；不能把 GMM 检查器直接称为 VAE 式生成分布。

## 2026-09-17 可变深度搜索原型

新增隔离文件 `adaptive_search_prototype.py`，不修改 v20-rnn-mixture 冻结代码。它用 GRU 的事件/下一 q 先验做 event→q′→F 的 beam lookahead，在生成第二个点后才使用已有 mixture 检查，并只提交根动作；这是 AlphaGo 风格搜索原型，不是训练好的 AlphaZero value network。

开发集（32 个窗口、2 粒子、50 步）结果：固定深度 1 的 embedding RMSE 为 0.00573/0.01927/0.04109（10/25/50 步），固定深度 2 为 0.00617/0.02042/0.03514；最小深度 2、最大深度 3 的提前停止版本平均深度 2.29，RMSE 为 0.00617/0.02051/0.03535，失败率 0。它改善了长程相对深度 1，但还没有超过固定深度 2；而且这是贪心 beam 原型，不是与官方随机粒子基线完全同配置的公平比较。
